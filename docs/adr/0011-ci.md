# 0011. CI on GitHub Actions

- **Status:** Accepted
- **Date:** 2026-10-17

## Context

Every change, from a human or an agent, must be checked the same way before it merges.

## Decision

Use **GitHub Actions** on the public repository:

- On every pull request: lint, format check, type check, Vitest, and Playwright against a local Supabase started in the runner.
- A pull request that changes only `docs/` or `.md` files runs only the format check (`scripts/ci-docs-only.ts` decides). The job still runs, so the required check passes. Pushes to `main` always run everything.
- A daily scheduled job, `keepalive.yml`, that requests `/health/database` on the hosted app, so the free Supabase project doesn't pause ([0005](0005-supabase.md)). It can also be run by hand.
- Deploys to Cloudflare stay manual until the owner decides otherwise.

## How to use

Workflows live in `.github/workflows/`. The keepalive workflow (`keepalive.yml`) needs no secrets: it requests the public `/health/database` route of the Worker, which runs a query on the database. The workflow fails unless the response is `200`. Run it by hand from the Actions tab with **Run workflow**.

## Known limits

- Free and unlimited minutes for standard runners on public repositories.
- GitHub disables scheduled workflows in a public repo after 60 days with no repository activity.
- GitHub can delay scheduled runs. A daily keepalive leaves more margin under Supabase's 7-day pause, so check the Actions history if a run is missed.

## Consequences

The same checks for humans and agents, at no cost.
